Only CreateDXGIFactory / CreateDXGIFactory1 / CreateDXGIFactory2 are
implemented by proxy_dll -- see dllmain.cpp for rationale (the other 17 are
undocumented/internal and used only by other Microsoft system DLLs loading
dxgi.dll directly from System32/SysWOW64, never through a game-directory
proxy).

Linker note (so this isn't re-discovered the hard way): MSVC's link.exe does
NOT support GNU ld/binutils-style ".def forwarder" syntax
(`EntryName=Module.Function` with no matching real symbol) -- confirmed by
direct experiment, fails with LNK2001 on both x86 and x64. Real proxy-DLL
projects (ReShade, Special K, ENB-style wrappers) instead write real typed
trampoline functions for the handful of exports that matter and lazy-load the
real system DLL by full path. That's what proxy_dll/dllmain.cpp does.
